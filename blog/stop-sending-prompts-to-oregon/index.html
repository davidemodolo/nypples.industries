Why European Companies Should Stop Sending Prompts to Oregon.

Product June 28, 2026 · 11 min read

A typical European startup using a US-based AI API sends every customer prompt, system instruction, and RAG context across the Atlantic. GDPR Article 28 mandates a documented chain of sub-processors for every data flow. How many of your clients have read OpenAI’s DPA? We built Nypples because the answer shouldn’t be “none.”

The invisible data export

When a Hamburg-based legal-tech startup sends a client’s case documents to a US-hosted LLM API, they’re not just “using AI.” They’re exporting personal data to a third country. GDPR Article 44 through 49 govern these transfers. The legal basis for US transfers under the EU-US Data Privacy Framework exists on paper, but it requires the US-based processor to be certified under the framework — and many AI API providers have ambiguous certification status.

Even when certification exists, Article 28 requires a Data Processing Agreement (DPA) that documents every sub-processor in the chain. For a typical US AI API call, that chain might include: the API provider, their cloud infrastructure provider (AWS/GCP/Azure), any third-party content moderation APIs, logging and monitoring services, and CDN edge nodes. Each link is a potential GDPR exposure point.

Most European developers using these APIs have never read the DPA. Most couldn’t list the sub-processors. This isn’t negligence — the documentation is deliberately opaque. But ignorance isn’t a defense under GDPR.

What Article 28 actually requires

The regulation is specific. Processors must:

  • Process personal data only on documented instructions from the controller
  • Ensure persons authorized to process the data have committed themselves to confidentiality
  • Implement appropriate technical and organizational measures (encryption, access control, audit logging)
  • Not engage another processor without prior specific or general written authorization
  • Assist the controller in responding to data subject requests
  • Delete or return all personal data at the end of the service
  • Make available all information necessary to demonstrate compliance

When you use a US-based API, you’re relying on their self-attestation for every one of these points. If their DPA says “we may use sub-processors at our discretion,” you’ve already lost chain-of-custody. This is why enterprise procurement teams spend months on vendor security assessments before signing an AI API contract.

The Schrems II shadow

The 2020 Schrems II ruling invalidated the Privacy Shield framework because US surveillance laws (FISA Section 702, Executive Order 12333) were deemed incompatible with EU fundamental rights. The current EU-US Data Privacy Framework attempts to address this, but legal challenges are already in progress (Schrems III is widely expected).

Until the legal situation stabilizes, any European company handling sensitive data — healthcare records, legal documents, financial transactions, HR data — has a clear risk incentive to keep that data within EU borders. The safest interpretation of GDPR is: if it never leaves the EU, you don’t need to worry about adequacy decisions.

What EU-resident inference looks like in practice

At Nypples, the data flow is deliberately simple:

  1. Your client sends an API request to api.nypples.industries
  2. Our API gateway in Trento validates the API key and routes to an available model shard
  3. The prompt is processed on Ascend 910C nodes in our colocation facility — within the same building as the gateway
  4. The completion is returned to the client
  5. No logs containing prompt or completion data leave the facility. Telemetry (token counts, latency, errors) is aggregated and anonymized before storage

There are zero sub-processors for inference. No CDN for API calls (our latency to Frankfurt is 14ms, to Amsterdam 18ms — a CDN adds complexity with no benefit). No third-party moderation API. No US-based cloud provider in the data path.

This isn’t a marketing claim. It’s a constraint we designed the infrastructure around. Our DPA is 6 pages because there’s not much to document when the data stays in one room.

The competitive argument

GDPR compliance isn’t just a legal checkbox — it’s a competitive advantage. European enterprise customers, government agencies, and regulated industries are actively seeking AI providers who can demonstrate EU-only data residency. The market exists. It’s growing. And it’s currently underserved by US-based API providers who view GDPR compliance as a cost center rather than a product feature.

We think that’s a mistake — and an opportunity.
